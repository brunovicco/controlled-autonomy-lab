# Controlled Autonomy Lab

> Same incident. Different levels of LLM autonomy.

A small Python reference implementation of the architecture continuum described by Anthropic:

**Augmented LLM → Workflows → Agent**

The repository runs the same production incident through six implementations so the trade-offs are observable instead of theoretical:

1. Augmented LLM
2. Prompt chaining
3. Routing
4. Parallelization
5. Evaluator-optimizer
6. Bounded tool-using agent

The point is not to prove that agents are better. The point is to show **where model judgment begins, where deterministic code still owns control flow, and what changes when the model owns the trajectory**.

## Why the same incident?

Every pattern receives `INC-001`:

- service: `checkout-api`;
- HTTP 5xx rises from `0.2%` to `8.7%`;
- p95 latency rises from `310ms` to `2840ms`;
- `v2.18.4` was deployed seven minutes before the incident;
- an upstream payment provider also shows increased latency.

The fixture intentionally creates a strong correlation without proving causality. A good analysis should treat the deployment or dependency as hypotheses until evidence confirms one of them.

## Control model

| Pattern | Who owns the path? | Model calls | Tool use | Main guard |
| --- | --- | ---: | ---: | --- |
| Augmented LLM | application | 1 | no | one bounded call |
| Chaining | application | 3 | no | fixed handoffs |
| Routing | application + classifier | 2 | no | route allowlist |
| Parallelization | application | 4 | no | fixed fan-out/fan-in |
| Evaluator-optimizer | application | variable | no | schema + revision budget |
| Agent | model | variable | yes | tool allowlist + step/tool budgets |

A workflow can use model judgment without giving the model control over what happens next. The agent is different: Claude chooses which evidence tool to call next based on what previous calls returned.

## Run it

Requirements:

- Python 3.13 or 3.14;
- `uv`;
- an Anthropic API key for live runs.

```bash
uv sync --frozen --all-groups
export ANTHROPIC_API_KEY="..."
```

The default model is `claude-sonnet-5`. Override it without changing code:

```bash
export CLAUDE_MODEL="claude-sonnet-5"
```

Run one pattern:

```bash
uv run python -m harness_example.entrypoints.autonomy_cli \
  run augmented --incident INC-001
```

Run the bounded agent:

```bash
uv run python -m harness_example.entrypoints.autonomy_cli \
  run agent --incident INC-001
```

Compare every pattern once:

```bash
uv run python -m harness_example.entrypoints.autonomy_cli \
  compare --incident INC-001
```

Measure trajectory variance across repeated executions:

```bash
uv run python -m harness_example.entrypoints.autonomy_cli \
  repeat agent --incident INC-001 --runs 5
```

Live runs consume API tokens. The lab records token counts instead of embedding a price table because provider pricing changes independently of this repository.

## Metadata-only traces

Use `--trace-file` before the subcommand to append one JSONL record per execution:

```bash
uv run python -m harness_example.entrypoints.autonomy_cli \
  --trace-file traces/runs.jsonl \
  repeat agent --runs 5
```

Recorded fields are limited to:

- pattern;
- incident id;
- model/tool call counts;
- step trajectory;
- input/output token counts;
- latency.

Prompts, model answers, evidence content, credentials, and tool arguments are not written to the trace file.

## Agent safety boundary

The agent can call only five tools:

```text
get_service_metrics
get_recent_deployments
get_dependencies
search_runbook
get_previous_incidents
```

All are read-only. Deterministic application code also enforces:

- `max_steps=6`;
- `max_tool_calls=8`;
- exact tool-name allowlist;
- tool input must reference the active incident;
- no shell, restart, rollback, configuration mutation, or production write capability.

This is the practical delegation boundary: the model may decide **what to inspect next**, but it cannot expand its own authority.

## Evaluator-optimizer safety boundary

The evaluator must return a strict JSON contract:

```json
{"passed": true, "feedback": []}
```

Invalid output fails explicitly. Revision loops are finite (`max_revisions=2` by default) rather than open-ended.

## Claude Skill

The repository includes `.claude/skills/incident-analysis/SKILL.md` as a packaging example. It captures the repeatable procedure for operating this lab without broadening runtime permissions.

A Skill and an architecture pattern solve different problems:

- the **pattern** controls how execution proceeds;
- the **Skill** packages a reusable procedure and instructions.

## Why `a2a-otel-kit` is not wired in yet

[`a2a-otel-kit`](https://github.com/brunovicco/a2a-otel-kit) is designed for distributed trace continuity across A2A, MCP, HTTP, and service boundaries. This lab is intentionally a single-process architecture comparison, so adding A2A/MCP infrastructure now would create complexity without a real distributed boundary.

A future distributed extension can split the orchestrator, evaluator, or evidence service into separate processes and then use `a2a-otel-kit` for metadata-only W3C/OTLP trace propagation.

## Quality gate

The repository retains the engineering harness quality runner:

```bash
uv run python scripts/quality_gate.py
```

That keeps model-based engineering assistance separate from deterministic Ruff, Mypy, Pytest, Bandit, dependency-audit, and architecture checks.
